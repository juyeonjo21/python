# Design.md — OCR 판정 보고서 앱 화면 디자인 가이드

현재 app.py에 적용된 화면 디자인을 정리한 문서다. 새 기능을 넣거나 비슷한 Streamlit 앱을 만들 때 이 규칙을 따른다.
요구사항은 PRD.md, 작업 규칙은 CLAUDE.md를 따른다.

## 1. 디자인 원칙
1. **파이썬을 모르는 시험원도 버튼만으로 끝낸다.** 화면 위에서 아래로 따라 내려가면 작업이 끝나도록 단계 순서대로 배치한다.
2. **화면 문구는 모두 한국어로 쓴다.** 단, 단위(GHz, µW, dBm, dBµV/m)와 판정값(PASS, FAIL)은 업계 표기를 그대로 쓴다.
3. **사용자가 고칠 수 있어야 한다.** AI가 읽은 값은 그대로 확정하지 않고, 표에서 고치면 아래 단계(판정·보고서)에 바로 반영되도록 한다.
4. **모르는 값은 숨기지 않는다.** 비어 있는 값은 "-"로 보이고, 판정은 "확인필요"로 눈에 띄게 둔다.
5. **Streamlit 기본 테마를 쓴다.** 별도 CSS나 `.streamlit/config.toml` 테마를 넣지 않는다. 색은 판정값 강조에만 쓴다 (4장).

## 2. 페이지 구성

```
┌────────────┬──────────────────────────────────────────────┐
│ 사이드바     │ OCR 판정 보고서                    (st.title)  │
│            │                                              │
│ 설정        │ 1. 이미지 업로드                               │
│  API 키     │ 2. 데이터 추출                                 │
│  모델 안내   │ ── 추출 결과가 있을 때만 아래 표시 ──              │
│            │ 3. 결과 확인 및 수정                            │
│ 판정 기준    │ 4. 판정                                       │
│  CF, Limit │ 5. 보고서                                      │
│  주파수 기준  │                                              │
└────────────┴──────────────────────────────────────────────┘
```

- `st.set_page_config(page_title="OCR 판정 보고서", layout="wide")`: 표가 넓으므로 항상 **wide** 레이아웃을 쓴다.
- 제목은 `st.title` 하나만 쓴다.
- **사이드바:** 한 번 정하면 잘 바뀌지 않는 설정(API 키, 판정 기준)을 둔다. 묶음 제목은 `st.header`로 쓴다.
- **본문:** 작업 단계를 둔다. 각 단계 제목은 `st.subheader("N. 단계명")`처럼 **번호를 붙인 명사형**으로 쓴다.
- 앞 단계 결과가 없으면 다음 단계는 **아예 그리지 않는다.** 예를 들어 3~5단계는 `"results" in st.session_state`일 때만 보인다. 빈 표나 쓸 수 없는 버튼을 미리 보여주지 않는다.
- 새 단계를 추가하면 마지막 번호 다음으로 붙이고, 순서는 작업 흐름을 따른다.

## 3. 구성요소 사용 규칙

| 용도 | 사용 요소 | 현재 적용 예 |
|---|---|---|
| 주요 동작 (단계당 1개) | `st.button(type="primary")`, `st.download_button(type="primary")` | 추출 시작, 보고서 다운로드 |
| 보조 동작 | 기본(secondary) 버튼 | 결과 CSV 다운로드 |
| 실행할 수 없는 동작 | `disabled=True` | 업로드 전 [추출 시작] |
| 숫자 설정 | `st.number_input` + `step`·`format` 지정 | CF `%.1f`, 주파수 `%.4f` |
| 켜기/끄기 | `st.checkbox` | 주파수 기준 사용 |
| 다른 설정에 딸린 설정 | 상위 설정이 꺼지면 `disabled` | 주파수 하한·상한 |
| 비밀값 | `st.text_input(type="password")` | API 키 |
| 날짜 | `st.date_input` → 문자열 `YYYY-MM-DD` | 시험일 |
| 여러 입력칸 | `st.columns(3)`에 나눠 담기 | 보고서 시험 정보 |
| 이미지 미리보기 | `st.columns(5)` 격자, `caption=파일명`, `width="stretch"` | 썸네일 |
| 오래 걸리는 작업 | `st.progress(값, text="i/n 처리 중: 파일명")` | 추출 |
| 고칠 수 있는 표 | `st.data_editor` + `column_config` | 추출 결과 |
| 읽기 전용 표 | `st.dataframe` + pandas Styler | 판정 결과 |
| 핵심 숫자 | `st.columns(n)` + `st.metric` | 판정 요약 5칸 |
| 보충 설명 | `st.caption` | 업로드 장수, 표 수정 안내 |

### 표 규칙
- 항상 `hide_index=True`, `width="stretch"`로 쓴다.
- 열 이름은 한국어로 쓰고, 단위는 괄호 안에 넣는다. 예: `주파수 (GHz)`, `마진 (dB)`
- 고치면 안 되는 열(파일명 등)은 `disabled=[...]`로 막는다.
- 단위처럼 정해진 값만 들어가는 열은 `SelectboxColumn`으로 고르게 한다. 자유 입력은 받지 않는다.
- 판정 결과 표의 열 순서는 **식별(파일) → 변환값 → 계산값 → 판정 → 사유** 순으로 둔다.

## 4. 색상
색은 **판정값 글자에만** 쓰고, 글자를 굵게(`font-weight: bold`) 한다. 배경색은 쓰지 않는다.

| 의미 | 값 | 색상 | 비고 |
|---|---|---|---|
| 합격 | PASS | `#1a7f37` (초록) | |
| 불합격 | FAIL | `#cf222e` (빨강) | |
| 확인 필요 | 확인필요 | `#9a6700` (황갈) | 경고 의미. 밝은 노랑은 흰 배경에서 읽기 어려워 쓰지 않는다 |

- 새 상태가 생기면 이 표에 먼저 추가하고, app.py의 `_color` 함수 한 곳에서만 색을 지정한다.
- 판정 문자열은 `judge.PASS / judge.FAIL / judge.CHECK` 상수를 쓴다. 화면 코드에 글자로 직접 적지 않는다.

## 5. 숫자·단위 표기

| 항목 | 화면 | 보고서(docx) |
|---|---|---|
| 주파수 | GHz, 소수 6자리 (`2.405095`) | MHz, 소수 3자리 (`2405.095`) |
| 전력 | µW, 소수 3자리 | µW, 유효숫자 6자리 (`641.83`) |
| dBm, dBµV/m, 마진 | 소수 2자리 | 소수 2자리 |
| CF, Limit | 소수 1자리 | 소수 1자리 |
| 값 없음 | `-` | `-` |

- 마이크로는 micro sign `µ`(U+00B5)로 쓴다. `u`, `μ`(그리스 문자)는 입력으로만 받는다.
- 판정은 화면에 보이는 자릿수와 맞춘다. 마진은 소수 2자리로 반올림한 뒤 판정한다.

## 6. 문구 작성 규칙
- **버튼:** "동사 명사형"으로 짧게 쓴다. 예: `추출 시작`, `보고서 다운로드`
- **안내 문구:** 존댓말("~해 주세요", "~할 수 있습니다")로 쓰고, 무엇을 하면 되는지 함께 알려준다.
  - 예: `사이드바에 API 키를 입력해 주세요.`
  - 예: `문서번호를 입력하면 보고서를 내려받을 수 있습니다.`
- **상태·요약:** 가운뎃점(·)으로 나열한다. 예: `총 20건 · 판독 불가 2건 (그중 추출 실패 0건)`
- **판정 사유:** 명사형으로 짧게 쓰고, 여러 개면 `; `로 잇는다. 예: `주파수 2.407000 GHz가 허용 범위(2.4035~2.406 GHz) 밖; 마진 -0.42 dB (Limit 초과)`
- 실패 메시지에는 예외 종류만 쓴다. API 키 등 민감정보가 섞일 수 있는 원문 오류는 보여주지 않는다. 예: `추출 실패: AuthenticationError`

## 7. 메시지 종류

| 상황 | 요소 | 예 |
|---|---|---|
| 다음 할 일 안내 | `st.info` | 문서번호 입력 안내 |
| 사용자가 빠뜨린 입력 | `st.warning` | API 키 없음 |
| 잘못된 설정값 | `st.error` | 주파수 하한 > 상한 |
| 부가 설명 | `st.caption` | 키 보관 방식, 모델명, 장수 |

- 한 이미지가 실패해도 화면을 멈추지 않는다. 결과 표에 "추출 실패"로 남기고 다음 이미지를 계속 처리한다.

## 8. 상태와 동작 흐름
- 단계 사이의 데이터는 `st.session_state`로 넘긴다.

  | 키 | 내용 |
  |---|---|
  | `api_key` | 화면에서 입력한 API 키. 세션에만 두고 파일·로그에 남기지 않는다 |
  | `results` | AI 추출 원본 |
  | `edited_results` | 사용자가 고친 표 |
  | `judged`, `summary` | 판정 결과 (보고서 단계에서 사용) |

- 새로 추출하면 `edited_results`를 지워서 이전에 고친 값이 섞이지 않게 한다.
- 판정은 버튼 없이 **즉시 다시 계산**한다. 사이드바 기준이나 표 값을 바꾸면 판정·요약·보고서가 바로 바뀐다.
- 다운로드 파일 이름은 `문서번호_RE보고서.docx`, `문서번호_RE결과.csv` 형식으로 하고, 파일명에 쓸 수 없는 문자는 `_`로 바꾼다.

## 9. 출력물 디자인
- **보고서(docx):** `docs/report_template.docx`의 서식을 그대로 쓴다. 코드에서 글꼴·색·테두리를 바꾸지 않고 `{{ }}` 자리만 채운다. 측정 결과 표는 템플릿 행을 복제해 늘린다.
- **특이사항:** 한 줄에 한 항목씩 쓴다. 형식은 `No.N 파일명: 판정 — 사유 (판독 비고: …)`이고, 해당 항목이 없으면 `특이사항 없음`으로 쓴다.
- **CSV:** 엑셀에서 한글이 깨지지 않도록 `utf-8-sig`로 저장한다. 열 이름은 한국어로 쓰고 단위는 괄호에 넣는다.

## 10. 새 화면 기능 추가 체크리스트
- [ ] 작업 순서에 맞는 번호를 붙인 `st.subheader`를 넣었는가
- [ ] 앞 단계 결과가 없을 때 이 단계를 숨겼는가
- [ ] 주요 버튼은 단계당 하나만 `primary`인가
- [ ] 문구가 한국어·존댓말이고, 단위가 괄호 안에 있는가
- [ ] 숫자 자릿수가 5장 표와 같은가
- [ ] 색은 4장의 판정 색만 썼는가
- [ ] 빈 값이 `-`와 "확인필요"로 보이는가
- [ ] API 키·민감정보가 화면 메시지나 파일에 노출되지 않는가
- [ ] 계산은 judge.py에 두고, 화면 코드(app.py)에는 화면만 두었는가
- [ ] tests/에 테스트를 추가하고 `python3 -m pytest -q`를 실행했는가
