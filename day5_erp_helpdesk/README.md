# ERP 문의 관리 시스템 (ERP Helpdesk)

사내 직원이 ERP 문의·개선 요청을 등록하고, 경영지원실 ERP 담당자가 **접수 → 직무 배정 → 답변 → 처리 완료**까지 처리 과정을 관리하는 웹 시스템입니다.
단순 게시판이 아니라 모든 상태 변경을 이력(History)으로 남기고, 처리 상황을 웹 알림과 이메일로 알려 줍니다.

## 주요 기능

| 구분 | 내용 |
|---|---|
| 문의 | 등록(카테고리·우선순위·첨부, 이미지 썸네일), 목록(상태 탭·검색·필터, HTMX로 새로고침 없이 갱신), 상세(처리 메뉴·답변/내부 메모·진행 내역) |
| 처리 | 상태 변경(보류·반려는 사유 필수), 담당 직무(백엔드/프론트/기획) 지정, 모든 변경을 History에 기록 |
| 알림 | 웹 알림(벨·패널·전체 알림 페이지, 60초 자동 갱신) + 이메일 알림(채널 정책 표로 관리) |
| 기타 | 홈 대시보드, 공지사항, 통계(Chart.js), 관리 메뉴, 역할별 권한(USER / AGENT / ADMIN) |

기술 스택: Python 3, Django 5.2, SQLite(개발), Django 템플릿 + Tailwind CSS·HTMX·Chart.js(CDN)

## 실행 방법

```bash
# 1. 가상환경 만들기·켜기 (처음 한 번)
python3 -m venv .venv
source .venv/bin/activate

# 2. 패키지 설치
pip install -r requirements.txt

# 3. 설정 파일 만들기 (처음 한 번) → .env를 열어 SECRET_KEY를 채움
cp .env.example .env

# 4. DB 테이블 만들기
python manage.py migrate

# 5. 샘플 데이터 만들기 (--reset 을 붙이면 문의·공지·알림을 지우고 다시 생성)
python manage.py seed_data

# 6. 서버 실행
python manage.py runserver 8001

# (선택) 자동 테스트 - 알림 정책·화면·권한 33개
python manage.py test
```

접속: http://127.0.0.1:8001/ · 관리자 페이지: http://127.0.0.1:8001/admin/

## 이메일 알림

### 구현 범위

**1) 알림 정책 - `notifications/policy.py`의 `CHANNELS` 표**

상황별로 웹 알림과 이메일을 켜고 끄는 표가 파일 맨 위에 있습니다. 정책을 바꿀 때는 이 표만 고치면 됩니다.

| 상황 | 받는 사람 | 웹 알림 | 이메일 |
|---|---|---|---|
| 문의 등록 | 활성 담당자 전원 | O | 우선순위가 **긴급**일 때만 |
| 문의 등록(접수 확인) | 요청자 | X | X (템플릿은 남겨 둠, 표에서 다시 켤 수 있음) |
| 직무 지정 | 해당 직무 담당자 | O | X |
| 답변 등록 | 요청자 | O | O |
| 사용자 코멘트 | 배정 직무 담당자 (미배정이면 전원) | O | X |
| 상태 변경 | 요청자 | O (모든 상태) | 처리 완료·보류·반려만 (보류·반려는 사유 포함) |
| 내부 메모 | - | X | X |

- 공통 규칙: 행동한 본인 제외, 받는 사람 중복 제거, 비활성 계정 제외
- 답변을 등록하면 직무 자동 지정·'답변 완료' 자동 변경이 함께 일어나지만, 알림은 **답변 1건만** 보냅니다(`notify=False`).
- 요청자에게 보이는 메일·알림에는 담당자 개인 이름 대신 `ERP 담당자(백엔드)`처럼 직무만 표시합니다.

**2) HTML 메일 템플릿 - `templates/emails/`**

- 상황별 6종(새 문의, 접수 확인, 직무 배정, 답변 등록, 요청자 코멘트, 상태 변경) × HTML·텍스트 두 벌
- 공통 레이아웃(`_base.html`): 흰 배경, 최대 폭 600px, 인라인 CSS(메일 프로그램 호환), 상태 배지, "문의 확인하기" 버튼
- 제목 형식: `[ERP 문의] ERP-2026-0041 답변 등록 - 비밀번호 재설정 요청`
- 보안: 내부 메모·첨부파일·다른 사용자의 개인정보는 넣지 않고, 문의 본문은 앞 200자만 미리보기로 넣습니다.
- 링크는 `SITE_URL` + 문의 상세 주소입니다. 로그인 전이면 로그인 후 그 문의로 이동하고, 해당 문의의 웹 알림도 읽음 처리됩니다.

**3) 발송 기록 - `EmailLog`**

- 받는 사람 1명마다 기록 1건: `PENDING`(대기) → `SENT`(발송 완료, 발송 시각) / `FAILED`(실패, 오류 내용)
- 이메일 주소가 비어 있으면 보내지 않고 `FAILED` / `이메일 주소 없음`으로 남깁니다.
- 관리자 화면: 관리 → 메일 발송 기록 (`/manage/email-logs/`), Django Admin

**4) 실패 처리와 재발송**

- 메일 발송이 실패해도 **문의 등록·답변 등 업무 처리는 항상 성공**합니다. 모든 오류를 잡아 EmailLog에 기록만 하고, DB 저장이 끝난 뒤(`transaction.on_commit(..., robust=True)`) 발송합니다.
- **실패 메일 재발송은 아직 구현하지 않았습니다.** 실패 기록과 오류 내용, 재시도 횟수 칸(`retry_count`)까지만 준비되어 있습니다. 재발송은 아래 "향후 과제"의 메일 발송 대기열과 함께 구현할 예정입니다.

**5) 웹 알림과의 역할 분담**

| | 웹 알림 | 이메일 |
|---|---|---|
| 목적 | 시스템 안의 **모든 처리 상황**을 빠짐없이 알림 | 시스템에 들어오지 않아도 **꼭 알아야 할 일**만 알림 |
| 대상 상황 | 등록·배정·답변·코멘트·모든 상태 변경 | 답변, 처리 완료·보류·반려, 긴급 문의 |
| 확인 방법 | 벨 배지·알림 패널·전체 알림 페이지 | 메일함 → "문의 확인하기" 링크 |
| 읽음 처리 | 알림 클릭, 문의 상세 열기, 모두 읽음 | - |

웹 알림 생성이 실패해도 이메일은 그대로 나가고, 둘 다 실패해도 업무 처리는 성공합니다.

### 현재 상태

**개발용 콘솔 출력 모드로 동작합니다. 실제로는 메일을 보내지 않습니다.**

`.env`의 `EMAIL_BACKEND=notifications.backends.ReadableConsoleEmailBackend` 설정에 따라, 메일 내용이 `runserver`를 실행한 터미널에 출력됩니다. Django 기본 콘솔과 달리 한글 제목이 깨지지 않게 받는 사람·제목·본문을 풀어서 보여 줍니다.

### 실제 사내 메일 서버를 제외한 이유

사내 그룹웨어 SMTP로 실제 메일을 보내려면 다음이 필요해서 이번 과제 범위에서 제외했습니다.

- **IT 승인**: 발송 전용 계정 발급, 이 서버의 IP를 메일 서버 접속 허용 목록에 등록, 메일 포트 방화벽 개방
- **사내 서버 배포**: 개발 PC가 아닌, 사내망 안에서 항상 켜져 있는 서버에 올려야 메일 속 링크(`SITE_URL`)가 다른 직원에게도 열림

### 운영 전환 방법

**1단계 - IT에서 받을 정보**

| 항목 | 예시 / 비고 |
|---|---|
| SMTP 서버 주소 | `mail.회사도메인` |
| 포트와 암호화 방식 | 587(STARTTLS) / 465(SSL) / 25(내부 릴레이) |
| 인증 방식 | 계정 로그인인지, 서버 IP 허용(인증 없음) 릴레이인지 |
| 발송 전용 계정·비밀번호 | `erp-helpdesk@회사도메인` (Exchange는 `도메인\아이디` 형식일 수 있음) |
| 접속 허용 IP 등록 | ERP Helpdesk 서버의 IP |
| 방화벽 개방 | 서버 → 메일 서버 포트 |
| 발신 주소 표시 이름 | `ERP Helpdesk <erp-helpdesk@회사도메인>` |
| SPF/DKIM 설정 | 메일이 스팸함으로 가지 않도록 |

**2단계 - `.env`에서 바꿀 값** (비밀번호는 `.env`에만 적고 코드·GitHub에는 올리지 않습니다)

```ini
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=mail.회사도메인
EMAIL_PORT=587
EMAIL_USE_TLS=True
EMAIL_USE_SSL=False
EMAIL_HOST_USER=erp-helpdesk@회사도메인
EMAIL_HOST_PASSWORD=(IT에서 받은 비밀번호)
EMAIL_TIMEOUT=10
DEFAULT_FROM_EMAIL=ERP Helpdesk <erp-helpdesk@회사도메인>
EMAIL_REDIRECT_TO=
SITE_URL=http://(사내 서버 주소)
```

| 방식 | 포트 | `EMAIL_USE_TLS` / `EMAIL_USE_SSL` | 계정·비밀번호 |
|---|---|---|---|
| 인증 + STARTTLS (권장) | 587 | True / False | 필요 |
| 사내 내부 릴레이 | 25 | False / False | 비움 (서버 IP 허용 등록 필요) |
| SSL 전용 | 465 | False / True | 필요 |

Microsoft 365·Gmail 예시는 `.env.example` 아래쪽 주석에 있습니다.

**3단계 - 연결 확인**

```bash
python manage.py send_test_email 내주소@회사도메인
```

현재 설정(비밀번호는 가림)을 보여 준 뒤 시험 메일 1통을 보냅니다. 실패하면 원인과 확인할 것을 한국어로 알려 줍니다.

| 출력되는 원인 | 주로 확인할 것 |
|---|---|
| 인증 실패 | 계정 형식(전체 주소 / `도메인\아이디`), 비밀번호, 계정의 SMTP 인증 허용 |
| 연결 시간 초과 | 방화벽, 사내망·VPN, 서버 주소·포트 |
| TLS/SSL 암호화 연결 실패 | 포트와 암호화 조합 (587=TLS, 465=SSL) |
| 서버가 STARTTLS를 지원하지 않음 | 내부 릴레이(25)라면 TLS=False |
| 발신 주소 거부 | `DEFAULT_FROM_EMAIL`과 로그인 계정 일치, 대리 발송 권한 |
| 연결 거부 / 서버 주소를 찾을 수 없음 | 포트, 서버 이름 오타 |

**4단계 - `EMAIL_REDIRECT_TO` 비우기**

개발 중에는 `EMAIL_REDIRECT_TO=내주소`를 넣으면 모든 알림 메일이 그 주소 한 곳으로만 가고, 제목 앞에 `[원래 수신: 원래주소]`가 붙습니다(샘플 계정 주소가 가짜이기 때문). **운영에서는 반드시 빈 값**으로 두어야 실제 받는 사람에게 갑니다.

**5단계 - `SITE_URL`을 사내 서버 주소로 변경**

메일의 "문의 확인하기" 링크 앞부분입니다. `http://127.0.0.1:8001` 그대로 두면 받는 사람의 PC 자신을 가리켜 링크가 열리지 않습니다.

### 메일 테스트 방법

**① 콘솔 출력 (기본값, 설치 없음)**

`.env`가 기본 설정이면 `runserver` 터미널에 메일이 출력됩니다.
예) `user1`로 문의를 등록하고 `agent1`로 답변하면, 터미널에 user1 앞으로 `[ERP 문의] … 답변 등록 - …` 메일 1통이 출력됩니다. 문의 등록 자체는 우선순위가 '긴급'일 때만 담당자들에게 메일이 나갑니다.

**② Mailpit (가짜 메일함에서 HTML 메일까지 확인)**

[Mailpit](https://mailpit.axllent.org/)은 메일을 실제로 보내지 않고 받아서 웹 화면에 보여 주는 개발용 메일 서버입니다.

```bash
# 설치·실행 (둘 중 하나)
brew install mailpit && mailpit
docker run -d --name mailpit -p 8025:8025 -p 1025:1025 axllent/mailpit
```

`.env`를 아래처럼 바꾸고 서버를 다시 시작하면, 보낸 메일을 http://127.0.0.1:8025 에서 HTML 화면 그대로 볼 수 있습니다.

```ini
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=127.0.0.1
EMAIL_PORT=1025
EMAIL_USE_TLS=False
EMAIL_USE_SSL=False
EMAIL_HOST_USER=
EMAIL_HOST_PASSWORD=
```

확인: `python manage.py send_test_email test@example.com` → Mailpit 화면에 시험 메일이 보이면 정상입니다.
